; Source of truth for BOTH implementations: the Java compiler (content, SmallcapsFont) and the
; studio (webui, lib/gui/font/smallcaps.ts) read this exact file, so the preview is the compiled
; sheet. Widths are not stored: they are the client's bitmap rule applied to these pixels
; (advance = rightmost ink column + 1, then + 1 px of spacing), and fixtures/gui/smallcaps/advances.txt
; pins the resulting table for both sides.
;
; Format. Blank lines and lines starting with ';' are ignored. Header keys: cell <w> <h> (the
; sheet cell, px), cap (capital height, px), small (small-cap height, px), space (advance of a
; space). Each `glyph U+XXXX c` line starts one glyph and is followed by exactly seven rows
; (rows 0 to 6), each row a string of '#' (ink) and '.' (none), at most cell-width long.
;   row 0      top of a capital; the baseline is the bottom of row 5
;   rows 1-5   the body of capitals and digits (cap = 6 rows)
;   row 6      descenders only (commas, semicolons, brackets, bars, underscore)
; A lowercase glyph is a small capital: its rows 1-5 sit on the same baseline with row 0 blank.
